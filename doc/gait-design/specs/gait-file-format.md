# Spec: Gait File Format

> Defines the `.gait` JSON intermediate format and the compiled C header format.
> See also: `blender-rig-and-export.md` (how gaits are created), `esp32-playback-engine.md` (how they're consumed).

---

## 1. Design Principles

- **Sparse keyframes** — store only inflection points, not every frame. The ESP32 interpolates.
- **Time in milliseconds** — decoupled from Blender FPS. Conversion happens at export.
- **Angles in servo degrees (0–270)** — not radians, not Blender-internal values.
- **Per-keyframe interpolation** — each keyframe says how to interpolate *to the next one*.
- **Neutral pose bookends** — first and last keyframe on every track must equal the neutral pose.

---

## 2. `.gait` JSON Format

### Schema

```json
{
  "name": "string — gait identifier, matches filename (e.g. walk_forward)",
  "version": 1,
  "duration_ms": "uint16 — total cycle duration in milliseconds",
  "fps_source": "uint8 — Blender FPS used during export (metadata only)",
  "interpolation_default": "string — default interp type: linear | cubic | constant",
  "neutral_pose": "[float × 12] — servo angles at neutral stance, indexed by servo_id",
  "tracks": [
    {
      "servo_id": "uint8 — physical servo index (0–11)",
      "name": "string — bone name for debugging (e.g. FL_shoulder)",
      "keyframes": [
        {
          "t": "uint16 — time in ms from cycle start",
          "angle": "float — servo angle in degrees (0.0–270.0)",
          "interp": "string (optional) — override interpolation to next keyframe"
        }
      ]
    }
  ]
}
```

### Example

```json
{
  "name": "walk_forward",
  "version": 1,
  "duration_ms": 800,
  "fps_source": 30,
  "interpolation_default": "cubic",
  "neutral_pose": [135, 135, 135, 135, 135, 135, 135, 135, 135, 135, 135, 135],
  "tracks": [
    {
      "servo_id": 0,
      "name": "FL_shoulder",
      "keyframes": [
        {"t": 0,   "angle": 135.0},
        {"t": 200, "angle": 150.0},
        {"t": 400, "angle": 145.0},
        {"t": 800, "angle": 135.0}
      ]
    },
    {
      "servo_id": 1,
      "name": "FL_hip",
      "keyframes": [
        {"t": 0,   "angle": 135.0},
        {"t": 200, "angle": 90.0, "interp": "linear"},
        {"t": 600, "angle": 180.0},
        {"t": 800, "angle": 135.0}
      ]
    }
  ]
}
```

### Rules

| Rule | Rationale |
|------|-----------|
| Every track must have `keyframes[0].t == 0` | Cycle starts at a defined position |
| Every track must have `keyframes[-1].t == duration_ms` | Cycle ends at a defined position |
| `keyframes[0].angle == keyframes[-1].angle == neutral_pose[servo_id]` | Seamless looping + clean gait transitions |
| `t` values must be strictly monotonically increasing | Simplifies binary search in firmware |
| `angle` must be within 0.0–270.0 | DSS-M15S physical range |
| If `interp` is omitted, use `interpolation_default` | Reduces verbosity |
| All 12 servos must have a track (even if only 2 keyframes at neutral) | Firmware assumes fixed 12-track layout |

### Interpolation types

| Type | Meaning | Use case |
|------|---------|----------|
| `linear` | Straight line between keyframes | Fast repositioning, predictable timing |
| `cubic` | Smooth ease-in/out: `3t² - 2t³` (smoothstep) | Natural-looking joint motion |
| `constant` | Hold previous value until next keyframe | Instant snap, useful for grip/release |

## 3. Compiled C Format

Generated by `gait_to_c.py`. One header per gait + a registry header.

### Per-gait header: `gait_walk_forward.h`

```c
// AUTO-GENERATED by gait_to_c.py — do not edit
// Source: gaits/walk_forward.gait
#pragma once

#include "gait_types.h"

static const keyframe_t gait_walk_forward_track0[] = {
    {0, 1350}, {200, 1500}, {400, 1450}, {800, 1350}
};

static const keyframe_t gait_walk_forward_track1[] = {
    {0, 1350}, {200, 900}, {600, 1800}, {800, 1350}
};

// ... tracks 2–11

static const gait_track_t gait_walk_forward_tracks[] = {
    {.servo_id = 0,  .num_kf = 4, .kf = gait_walk_forward_track0,  .interp = INTERP_CUBIC},
    {.servo_id = 1,  .num_kf = 4, .kf = gait_walk_forward_track1,  .interp = INTERP_CUBIC},
    // ...
};

static const gait_t GAIT_WALK_FORWARD = {
    .name        = "walk_forward",
    .duration_ms = 800,
    .num_tracks  = 12,
    .tracks      = gait_walk_forward_tracks,
};
```

### Registry header: `gait_registry.h`

```c
// AUTO-GENERATED — do not edit
#pragma once

#include "gait_walk_forward.h"
#include "gait_turn_left.h"
#include "gait_turn_right.h"
#include "gait_stand.h"

typedef struct {
    const char* name;
    const gait_t* gait;
} gait_entry_t;

static const gait_entry_t GAIT_REGISTRY[] = {
    {"walk_forward", &GAIT_WALK_FORWARD},
    {"turn_left",    &GAIT_TURN_LEFT},
    {"turn_right",   &GAIT_TURN_RIGHT},
    {"stand",        &GAIT_STAND},
};

#define NUM_GAITS (sizeof(GAIT_REGISTRY) / sizeof(GAIT_REGISTRY[0]))
```

### Data types: `gait_types.h`

```c
#pragma once
#include <stdint.h>

#define INTERP_LINEAR   0
#define INTERP_CUBIC    1
#define INTERP_CONSTANT 2

typedef struct {
    uint16_t time_ms;
    uint16_t angle_x10;   // degrees × 10 → 0–2700 fits in uint16_t (0.1° precision)
} keyframe_t;

typedef struct {
    uint8_t          servo_id;
    uint8_t          num_kf;
    const keyframe_t* kf;
    uint8_t          interp;
} gait_track_t;

typedef struct {
    const char*          name;
    uint16_t             duration_ms;
    uint8_t              num_tracks;
    const gait_track_t*  tracks;
} gait_t;
```

### Memory budget

| Item | Size |
|------|------|
| One keyframe | 4 bytes (2 × uint16) |
| One track (10 keyframes avg) | 40 bytes data + 4 bytes header |
| One gait (12 tracks) | ~530 bytes |
| 20 gaits | ~10.6 KB |
| ESP32 flash available | 4 MB |

## 4. Validation Rules (for `gait_validator.py`)

The validator script checks `.gait` files before compilation:

1. `duration_ms > 0`
2. Exactly 12 tracks, `servo_id` values 0–11 with no duplicates
3. Each track: keyframes sorted by `t`, first `t == 0`, last `t == duration_ms`
4. Neutral pose alignment: `keyframes[0].angle == keyframes[-1].angle == neutral_pose[servo_id]`
5. All angles within 0.0–270.0
6. All `interp` values are one of: `linear`, `cubic`, `constant`
7. At least 2 keyframes per track (start + end)
8. `name` matches filename (without `.gait` extension)

---

## 5. Future Considerations

- **Per-keyframe interpolation in C format:** Currently the C format uses per-track interpolation. If needed, per-keyframe interp can be added by extending `keyframe_t` with a `uint8_t interp` field (+1 byte per keyframe, with padding → +2 bytes).
- **Compression:** If gait count grows very large, keyframe deduplication across tracks (shared time columns) could save space. Not needed at current scale.
- **Binary format:** If JSON parsing is ever needed at runtime (e.g. loading gaits over WiFi), a binary `.gaitb` format could replace the C compilation step. Current approach (compile to C) is simpler.
