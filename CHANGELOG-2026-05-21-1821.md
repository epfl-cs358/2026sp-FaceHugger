# Changelog — animation pipeline & on-board clip player

Plain-language summary of what changed on the `feat/animation-flow-integration`
branch, organised by phase and by group of work.

## Phase 0 — Exporter correctness & safety

### Safety
- Clamped servo angles to 0–180 with a warning so out-of-range commands can't drive the servos past their limits.

### Fixing the clip bake
- Fixed the bug where every exported clip was the same animation, so each clip now bakes its own motion.
- Added a headless Blender regression test proving a clip bakes independently of which clip is active.
- Added a warning when a joint moves too far between frames, to catch fast keyframes before they reach the robot.
- Added a warning when the scene frame rate is higher than recommended for robot export.

### Browser (JS) export
- Added checks that the exported JS uses the correct leg order, angle clamp, and frame timing.
- Gave the JS exporter a way to return the script without writing a file, fixing a broken dry-run export.
- Made the JS stream only send servos that changed, and pop an alert if it can't reach the robot.
- Added a Preview Robot Motion button that switches the clip between smooth and straight-line playback non-destructively.

### Tooling & docs
- Tracked the rig .blend with git-lfs and started tracking the exported clips so they show up in reviews.
- Added a one-command headless re-export of every clip and re-exported all five, verified each is now distinct.
- Added a motion-pipeline glossary, the Phase-0 plan, and tracked the upcoming IP, heatmap, and PyBullet-validator tasks.

## Phase 2 — On-board clip player

The robot can now play a named animation "clip" (e.g. "wiggle", "wave") entirely
on its own, triggered by a single command — no streaming from a laptop. It plays
the clip once, then eases back to the standing pose and goes idle.

### Exporter — one bundled header for all clips
- Renamed the export folder from `exported_gaits/` to `exported_clips/`, because it holds one-shot *clips*, not looping *gaits*.
- Added a bundled export that packs every clip into a single `clips_all.h` (plus a `clips_manifest.json` listing each clip's name and id) for the firmware to compile in.
- Baked the 2/3 amplitude scaling into that header up front, so the firmware never has to re-scale — it just plays the numbers as-is.
- Made the bundled export refuse bad input loudly: empty clips, out-of-order frame timing, two clips whose names collide in C, or clips longer than the timeline can represent.
- Documented the "pre-scaled, math-space" rule so the exporter and firmware can never silently disagree on what the numbers mean.

### Firmware — playing clips on the robot
- Pulled the per-leg angle-to-servo conversion (which was copy-pasted in three gait functions) into one shared, unit-tested helper, with the gait output proven unchanged.
- Added clip playback that smoothly interpolates between the recorded frames, and a small state machine that runs a clip once and then returns to the neutral stand over half a second before going idle.
- Added a non-blocking "ease to angle over N milliseconds" servo move (used for that return-to-stand) so the robot never freezes while 12 servos glide home.
- Added the `playClip` / `tickClip` engine that drives all of the above, sharing the robot's single "one motion at a time" model — starting a clip pre-empts a gait, and vice-versa.
- Added a new WebSocket command, `{"T":7,"c":<id>}`, to play a clip by id, and documented it in the API spec.
- Added a parity test that proves the firmware's angle conversion matches the Blender exporter's to within 1°, so a clip looks the same on the robot as in the browser.

### Integration
- Compiled the real five-clip bundle into the firmware and confirmed everything builds and all on-host tests pass against it.

### Fixes found along the way
- Fixed a long-standing firmware bug where a malformed calibration command would fall through and make the robot start walking; a bad calibrate packet is now safely ignored.
- Hardened the clip test fixture so it can't clash with the real generated clip data, keeping the tests valid after the real clips are compiled in.

## 2026-05-23 — Clip-panel export & preview UX

### Browser (JS) export
- Added an editable ESP IP field to the Export panel so the exported browser JS points at the robot's current board address — the IP can change (Wi-Fi AP default vs. a DHCP lease), and it's now set at export time instead of being hard-coded. The WebSocket URL and the "how to run" instructions both follow it; blank falls back to 192.168.4.1, and the port stays fixed at 81.

### Preview
- Made the Preview Robot Motion button show which mode the active clip is in: depressed and labelled LINEAR while you're previewing the robot's straight-line playback, raised and labelled BEZIER while you're authoring. The state is read live from the clip's keyframes, so it can never disagree with what the button actually does.

### Verification
- Audited the five exported clips against the firmware for hardware safety (wire-protocol match, angle clamping, slew rate, packet timing) and confirmed they can't damage the servos as played. Two follow-ups noted: the back-left shoulder is authored past the servo's range and silently clamps (played motion differs from the authored motion), and the firmware's calibrate command doesn't yet bounds-check its leg/servo index.

### Tooling
- Ignored the local `.work/` agent scratch directory so research notes stay out of source control.
