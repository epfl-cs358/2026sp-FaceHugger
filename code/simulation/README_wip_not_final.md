# URDF Pipeline

Generates `facehugger.urdf` from live Fusion 360 geometry, exports STL meshes,
and produces a robot description loadable in PyBullet for physics simulation or
Blender for animation and gait authoring.

```
cad/scripts/ExportBodiesToURDF/    Fusion 360 script — reads assembly, writes JSON + STLs
code/simulation/
  facehugger_config.yaml           hierarchy definition — which bodies form which URDF links
  generate_urdf.py                 reads JSON + config, writes facehugger.urdf
  facehugger.urdf                  generated output
  fusion_export.json               generated by Fusion script (gitignored)
  exported_meshes/                 STLs generated by Fusion script (one per link)
  meshes/                          hand-curated / reference STLs
  simulate.py                      PyBullet simulation entry point
```

---

## CAD preparation in Fusion 360

The generator needs to know where each joint sits in 3D space and what axis it
rotates around. Rather than hardcoding these values, they are read from Fusion
construction geometry — so updating the CAD automatically updates the URDF.

For each joint, define one **construction axis** and one **construction point**
in the leg assembly component, following the naming convention the config references:

| Fusion name                              | Joint                          |
| ---------------------------------------- | ------------------------------ |
| `BodyToLink1Axis` / `BodyToLink1Point`   | shoulder — body → link1, yaw Z |
| `Link1ToLink2Axis` / `Link1ToLink2Point` | hip — link1 → link2, pitch X   |
| `Link2ToLink3Axis` / `Link2ToLink3Point` | knee — link2 → link3, pitch X  |

Place each construction point at the physical servo output shaft center. The axis
direction becomes the URDF `<axis xyz=...>` vector — use Fusion's cylinder/edge
snapping to align it precisely. For leg mount positions, define one construction
point per leg on the body skeleton (`LegMountFR`, `LegMountFL`, `LegMountBR`,
`LegMountBL`) to set each shoulder joint's origin in body frame.

The Fusion script traverses the full assembly recursively through all external
references, collecting body positions, construction axis origins and directions,
construction point positions, and physical properties (mass, center of mass,
inertia tensor). These are written as `fusion_export.json` and `fusion_export.txt`,
and the relevant link geometries are exported as STL files directly into
`exported_meshes/`.

## Step 1 — Run the Fusion script

Open `FullBodyAssembly` in Fusion 360, then:

```
Shift+S → Scripts and Add-Ins → ExportBodiesToURDF → Run
```

All output paths are resolved relative to this script's location in the repo —
no configuration needed regardless of where the repo is cloned.

Outputs written to `code/simulation/`:
- `fusion_export.json` — consumed by `generate_urdf.py`
- `fusion_export.txt` — human-readable tree for sanity checking
- `exported_meshes/*.stl` — one STL per entry in `MESH_EXPORTS` at the top of the script

To change which meshes are exported, edit `MESH_EXPORTS` in `ExportBodiesToURDF.py`:

```python
MESH_EXPORTS = {
    "Link1:1":       "leg_shoulder.stl",
    "Link2:1":       "leg_upper.stl",
    "Link3:1":       "leg_lower.stl",
    "BottomPlate:1": "QuadrupedBody.stl",
}
```

Toggle `COLLECT_PHYSICS = False` to skip inertia computation if the run is slow.
Toggle `VISIBLE_ONLY = False` to include hidden geometry.

Re-run this step whenever geometry changes in Fusion.

## Step 2 — Generate the URDF

### Environment setup

pybullet has no prebuilt macOS wheel on PyPI and fails to compile from source on
recent macOS/clang combinations. **Use conda with conda-forge**, which ships a
prebuilt binary for macOS arm64.

Install [Miniforge](https://conda-forge.org/download/) if you don't have conda:

```bash
brew install miniforge
```

Create and activate the project environment:

```bash
conda create -n facehugger python=3.11
conda activate facehugger
conda install -c conda-forge pybullet
pip install -r requirements.txt
```

> Always activate the env before running any script in this folder:
> `conda activate facehugger`

### Run

```bash
python generate_urdf.py
```

Optional flags:

```bash
python generate_urdf.py \
  --export fusion_export.json \
  --config facehugger_config.yaml \
  --out facehugger.urdf
```

The generator reads all joint coordinates and inertial data from
`fusion_export.json`, and the robot hierarchy — which bodies form which links,
which construction geometry defines each joint, and how the four legs are
instantiated from the single template — from `facehugger_config.yaml`.

Edit `facehugger_config.yaml` when the kinematic structure changes (joint limits,
mesh filenames, mount point names). For geometry-only changes, re-running the
Fusion script and then the generator is sufficient.

## Step 3 — Simulate in PyBullet

```bash
python simulate.py             # standing stance
python simulate.py --walk      # static walk gait (FL → RR → FR → RL)
python simulate.py --trot      # trot gait (diagonal pairs)
python simulate.py --wall-flip
python simulate.py --headless  # no GUI, for quick checks
```

## Downstream: Blender import

The URDF and STL meshes can be imported into Blender using a patched version of
[blender-urdf-importer](https://github.com/Victorlouisdg/blender-urdf-importer).
Required patches: swap `collada_import` for `import_mesh.stl`, remove deprecated
`use_auto_smooth` calls (removed in Blender 4.1+), and replace ROS path resolution
with a direct path to `exported_meshes/`. Blender 5.1 uses Python 3.13 internally
— Blender scripts run inside Blender's own interpreter and do not share this conda
environment.

## Robot specs

| Parameter    | Value                              |
| ------------ | ---------------------------------- |
| Servos       | QYRC DS3230MG                      |
| Torque       | 30 kg·cm = 2.94 N·m @ 6V           |
| Servo weight | ~60 g                              |
| Range        | 180° (−90° to +90°)                |
| DOF          | 12 (3 per leg × 4 legs)            |
| Leg geometry | L1 = 80 mm, L2 = 75 mm, L3 ≈ 95 mm |

| Joint                   | Axis  | URDF direction |
| ----------------------- | ----- | -------------- |
| Shoulder (body → link1) | Yaw   | Z `(0, 0, 1)`  |
| Hip (link1 → link2)     | Pitch | X `(1, 0, 0)`  |
| Knee (link2 → link3)    | Pitch | X `(1, 0, 0)`  |

FL and BR legs have `rpy_z = 180°` on the shoulder joint to mirror the leg frame.
